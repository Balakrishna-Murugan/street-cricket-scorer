Street Cricket Scorer — Architecture & Cheat Sheet

1) High-level Flow Diagram

Description: The browser client (React) calls the Server (Node/Express) over REST JSON. The server persists match and player data in MongoDB via Mongoose. CI builds run on GitHub Actions; tests use Jest. The live scoring page maintains client-side match state and uses API endpoints to persist updates.

2) Tech stack (repository-specific)

Client

  • React (Create React App) + TypeScript
  • Material UI (MUI) for UI
  • Axios for API calls
  • Jest & React Testing Library for unit tests
  • Build: react-scripts (npm run build)

Server

  • Node.js + TypeScript
  • Express for HTTP API
  • Mongoose for MongoDB models
  • Mocha/Jest for server tests (where present)

Dev/CI/Infra

  • GitHub Actions for CI
  • Hosting: (project uses render.yaml — can deploy to Render or similar)
  • npm for package management

3) GitHub Actions & CI — Quick cheatsheet

Common workflow tasks you'll include in a CI workflow for this repo:

- actions/checkout@v3
- actions/setup-node@v4 (set node-version)
- npm ci (or npm install)
- npm run build (client)
- npm test (unit tests)
- run server lint/tests (tsc, node tests)
- upload-artifact / deploy steps

Typical job snippets (YAML):

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v4
        with: { node-version: '18' }
      - run: npm ci --prefix client
      - run: npm run build --prefix client
      - run: npm ci --prefix server
      - run: npm test --prefix client --silent
      - run: npm test --prefix server --silent

Use caching to speed up installs (actions/cache)
